Planned player journey & API usageParcours joueur prévu et utilisation de l’API

This public visual flow demonstrates how the planned desktop app will request the player's explicit consent, connect via Riot Sign On after approval, retrieve authorized match information, and use it for post-game aim-training analysis.

Ce parcours visuel public montre comment l'application Windows demandera le consentement du joueur, utilisera Riot Sign On après approbation, récupérera les matchs autorisés et les analysera après les parties.

Mockup only — not a live Riot integration.Maquette uniquement — aucune connexion Riot active.
Screens and numbers below are illustrative. No Riot credentials are requested, no login occurs, no live match data is collected, and no production API access is implied.
Les écrans et chiffres ci-dessous sont fictifs. Aucun identifiant Riot n’est demandé, aucune connexion n’a lieu et aucune donnée réelle n’est récupérée.

01 — Account linking journey01 — Connexion du compte

Four steps, with player opt-in.Quatre étapes, avec consentement du joueur.

STEP 01Open the appOuvrir l’application

Training features work locally without a Riot login. The player chooses the optional Match Stats page.

L'entraînement fonctionne sans compte Riot. Le joueur choisit d'accéder aux statistiques des matchs.

STEP 02Read privacy noticeLire les conditions

Clearly explain how match data is used, the player’s choice to opt in, and the visibility of data linked to an account.

Expliquer les usages des données, le consentement requis et leur visibilité après liaison du compte.

STEP 03Log in via RiotConnexion Riot

Redirect to Riot's official OAuth page. A secure backend handles the OAuth callback and credentials.

Redirection vers OAuth Riot. Un backend sécurisé gère le retour et les secrets.

STEP 04View own historyAfficher les matchs

Use authorized match details for post-game analytics and comparisons with aim-training sessions.

Utiliser les matchs autorisés pour l'analyse après partie et la comparaison avec l'entraînement AIM.

03 — Intended data handling03 — Traitement prévu des données

What the Riot API will be used forComment l'API Riot sera utilisée

Planned official endpointsEndpoints officiels prévus

GET /riot/account/v1/accounts/me
Identify the player after successful approved RSO login.Identifier le joueur après connexion RSO autorisée.

GET /val/match/v1/matchlists/by-puuid/{puuid}
Retrieve available match IDs for the opted-in player.Récupérer les identifiants des matchs du joueur consentant.

GET /val/match/v1/matches/{matchId}
Obtain permitted match details for after-game analysis.Obtenir les détails autorisés des matchs après la partie.

Security & fair-play safeguardsSécurité et fair-play

  • Explicit opt-in and data-visibility notice before linking
  • Consentement explicite et avertissement sur la visibilité des données
  • Secure backend for RSO client secrets and authorized tokens
  • Backend sécurisé pour les secrets RSO et tokens autorisés
  • No access to non-opted-in players' private stats
  • Aucun accès aux données privées des joueurs non consentants
  • No live tactical coaching or pre-match opponent scouting
  • Aucun conseil tactique en direct ni scouting d'adversaires
  • Account unlink and data deletion controls planned before launch
  • Déconnexion et suppression des données prévues avant publication
